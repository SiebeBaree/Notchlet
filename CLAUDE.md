# Notchlet

Native macOS notch app (Swift 6, SwiftUI, AppKit for windowing) that shows remaining agent CLI usage (Claude Code, Codex, Cursor, OpenCode) per rate-limit window, with a burn-rate verdict per window. LSUIElement agent, no dock icon, no main window. Hovering the notch expands a panel out of it: one provider shows its full breakdown, two or three show a summary gauge each with hover drill-in. At most three providers are active at once (`UsageStore.maxActiveProviders`); installed CLIs fill the slots in registration order and the settings toggles lock at the cap.

## Commands

- Build: `xcodebuild build -scheme Notchlet -destination 'platform=macOS'`
- Test: `xcodebuild test -scheme Notchlet -destination 'platform=macOS'` (Swift Testing, not XCTest)
- Format: `swiftformat .` (CI lints with `swiftformat --lint .`)

## Architecture

- `Notchlet/App/` entry point. Plain AppKit lifecycle (`main.swift`, no SwiftUI App scene); `AppDelegate` wires providers into `UsageStore`, creates the window controller, the update controller and analytics.
- `Notchlet/Analytics/` anonymous PostHog analytics (EU cloud). `AnalyticsEvent` is the complete typed catalog of what leaves the machine; `Analytics` is the SDK wrapper (opt-out toggle, daily heartbeat, provider super properties); `DeviceInfo` gathers hardware context. Never call `identify()`, never send usage numbers or credentials. Disabled entirely in DEBUG builds. The project key is substituted into `Notchlet/Info.plist` from the gitignored `Config/Secrets.xcconfig`, so it is never in source; builds without that file send nothing.
- `Notchlet/Updates/` Sparkle auto-update. `UpdateController` suppresses all scheduled-update popups (gentle reminders); the notch shows an update icon instead and install hands off to Sparkle's standard flow. Sparkle keys live in the partial `Notchlet/Info.plist` (merged into the generated one; the feed 404s until the repo is public, which is intended).
- `Notchlet/Notch/` the panel: `NotchPanel` (borderless non-activating NSPanel; it must be able to become key or the settings switches collapse the panel instead of toggling), `NotchWindowController` (positions it over the notch, virtual notch fallback for external displays), `NotchView` (SwiftUI, hover to expand), `NotchGeometry` (pure geometry, AppKit-free so it's unit-testable). The window is sized to the bare notch while collapsed and grows to `panelSize` only while expanded: every cursor move inside the window costs a SwiftUI hover hit-test, so the window is never larger than what it draws. The hosting view has `sizingOptions = []` because the controller owns the frame. `HistoryPane` is the third pane, at the same card width as the other two: scope chips, range tiles (the selected range feeds the model table), the graph and the models. `HistoryGraphs` holds the activity heatmap and the spend line, one `Canvas` each with one continuous-hover handler and a single tooltip overlay, never a view per cell, both sized by one aspect ratio so toggling never moves the rows below; `ActivityGrid` and `SpendSeries` are their pure models.
- `Notchlet/Usage/` the provider system. `UsageProvider` is the base protocol; endpoint-backed providers adopt `HTTPUsageProvider` and only supply the endpoint URL, auth headers per `AuthOption` and response mapping (`fetchUsage` is a shared default that walks the options the user's `AuthSelection` allows and reports the most specific `AuthProblem`; 401/403 map to `notAvailable(.rejected)`). Each provider lists its auth options in preference order (the CLI's own state first, a pasted secret last); `ProviderAuthSettings` stores the per-provider choice and `SecretStore` keeps pasted secrets in Notchlet's own keychain item, both keyed by provider id so a second account of one provider later is just another id. `CredentialSupport` has the common credential plumbing (home dir JSON, keychain items, Electron SQLite state, JWT claims). Keychain items are read by spawning `/usr/bin/security`, never through the Security framework: the CLI wrote the item with that tool so it stays on the access list, whereas a read as Notchlet prompts for the keychain password again after every token rotation (Claude Code rotates every 8 hours). Claude Code's credentials are cached until they expire so that read costs one process per token rather than one per poll; a rejection drops the cache and retries once, so a rotated token never shows as an error. Cursor's token is read from its `state.vscdb` by spawning `/usr/bin/sqlite3` read-only, so the app's database is never locked or modified. A new provider is one file plus a logo imageset and a line in `AppDelegate`, with a parsing test against a real response fixture.
- `Notchlet/History/` past usage, read from the CLIs' own logs the way ccusage, CodexBar and OpenUsage do it. `UsageHistorySource` is the per-provider protocol (a provider hands its source out through `UsageProvider.history`); every source normalizes into `UsageEvent` and `TokenCount`, and `UsageRollup` buckets those into `DailyUsage` rows per local day and model (`DayKey` is the only place a `Date` becomes a day). JSONL logs go through `LogDirectoryReader`, a generic actor over a `LogLineParser` that streams files in 256 KiB chunks, parses up to four files in parallel and remembers every file by size and mtime with its parser state, so a re-read only touches appended bytes. Claude Code deletes transcripts after 30 days, so `HistoryIngestor` seals every day older than yesterday into a JSON archive per provider under Application Support (`HistoryArchive`, `SealPlan`): today and yesterday are always recomputed from the logs, sealed days never change, and `coverageStart` marks where the archive can vouch for a day (earlier days are unknown, not zero). Cost is never stored: `ModelPrices` is a bundled table of API list prices, exact match after normalizing, and `UsageLedger` prices rows at read time, naming unpriced models rather than hiding them. `UsageHistory` is the observable store: ingest 5s after launch, hourly, on wake and when the pane opens onto data older than a minute, one source at a time. Codex (`CodexHistorySource`) reads `~/.codex/sessions` and `archived_sessions` (roots in order of preference, a file name seen earlier wins): the model comes from the preceding `turn_context`, each `token_count` counts by its `last_token_usage` delta with cached tokens subtracted out of input, a repeated total is a re-emitted snapshot, and a subagent or forked thread drops everything before its own first `task_started` because it replays its parent's history at spawn. OpenCode (`OpenCodeHistorySource`) queries every `opencode*.db` in its data directory through `sqlite3 -json` read-only (`CredentialSupport.sqliteRows`), hosted gateways only, and carries OpenCode's own per-message cost when it is positive. Cursor (`CursorHistorySource`) has no local log: it fetches the dashboard's usage export CSV with the same session cookie as the live provider (`CursorUsageProvider.sessionHeaders`), a year on the first read and the unsealed days after, and folds Cursor's model labels into vendor ids (`CursorModelNames`); it is account-wide. Static members of an actor default to main-actor isolation under this project's settings, so parsing helpers are marked `nonisolated`.
- `Notchlet/Share/` the share card: a 1200 by 675 PNG of the history pane's numbers, opened from the share icon in the corner strip. `ShareCard` is the pure model (`make` turns a `UsageLedger` into formatted text, an `ActivityGrid` or `SpendSeries` and model rows, with its own tests), `ShareCardView` draws it and `ShareRenderer` renders that view through `ImageRenderer` at 2x and copies or saves the PNG. The preview in `ShareEditorWindow` is the same view scaled down, so there is one layout. ImageRenderer has no window behind the view, so the glass is painted from gradients and nothing in the card may use a material or a blur. The heatmap and spend line are drawn by the static `draw` functions on `ActivityHeatmap` and `SpendChart`, shared with the pane through `GraphStyle`. The editor is its own activating `NSWindow` because the notch panel collapses on mouse-out and never becomes active; the app has no menu bar, so the window handles Cmd+C, Cmd+S, Cmd+W and Escape itself. Options persist under `share.*` defaults; days before coverage draw as a fainter cell and the header or footer says since when.
- `Notchlet/Secrets/` leaked keys in the CLIs' chats, found by betterleaks (MIT, by the Gitleaks authors) shipped as `Contents/MacOS/betterleaks`: `Scripts/fetch-betterleaks.sh` pins the version and checksum and downloads it into the gitignored `Vendor/`, run once after cloning and by CI before archiving; `Scripts/sign-nested.sh` signs it with the hardened runtime before notarization. arm64 only, so the feature is off on Intel (`Betterleaks.isAvailable`). `SecretScanSource` is the per-provider protocol (a provider hands one out through `UsageProvider.secrets`): files changed since a date, or rows piped to stdin for a database-backed CLI. `Betterleaks` spawns the binary on the background tier (`setpriority` with `PRIO_DARWIN_BG`, what `taskpolicy -b` does), validation off, `--confidence high`, and a `disabledRules` list of rules that were noise on real transcripts; the false positive reports in PostHog decide what joins it. `SecretFinding` is the pure model: keyed by a hash of the secret so a key pasted in forty chats is one finding and a rescan of an unchanged file adds nothing; what is stored (`SecretScanState`, one JSON file under Application Support) and shown is the first six and last two characters, never the secret. `SecretPolicy` drops placeholders, bare variable names and JWTs that have expired or have no expiry. `SecretScanSchedule` is the pure timing: the first full pass waits for two idle minutes and a cool Mac, then hourly over files by mtime, whole files rescanned. `SecretScanner` is the observable store and loop, one provider at a time; new findings bump `alertGeneration`, which `NotchView` answers by opening the notch for twelve seconds (deferred until the first mouse event when the user is away, through a one-shot global monitor). `SecretScanner.Status` feeds one status line (`SecretsPane.statusText`) to the empty pane, the settings page and the corner strip, where a spinner takes the key's slot while betterleaks runs. Claude Code and Codex have sources (`ClaudeCodeSecretSource`, `CodexSecretSource`, the latter with the same root preference as its history source). `SecretsPane` shows one finding at a time with three actions: How to solve this (notchlet.com/secrets-found with the rule and provider in the query), Ignore (forever, per secret) and Report false positive (the one event that carries a preview; the button exists only while analytics is on). A new provider is one `SecretScanSource` file plus `secrets` on the provider, with a test over a temp tree.
- Windows are whatever the plan meters: rolling sessions, weeks, a billing cycle (Cursor) or model pools on one cycle (Cursor's "Cursor models" and "Other models", Claude's per-model weekly). `UsageSnapshot.primaryWindow` is the shortest window, first among equals, so a provider whose windows share one cycle lists the headline first. OpenCode shows only OpenCode Go windows: Zen credits have no key-authenticated endpoint and browser cookies are off limits.
- Refresh cadence: `UsageStore` polls slowly while the panel is closed (user setting, 3-30 min, default 10) and every 60s while open; opening the panel makes anything older than 60s due immediately. `RefreshSchedule` is the pure per-provider timing model: 30s minimum spacing, Retry-After/exponential backoff on 429, flat 2 min retry on other errors. The panel footer labels data age past 2 min and names a rate-limited provider with its retry time.
- `BurnProjection` is the pace model, mirrored from CodexBar: average burn since the window started (elapsed derives from `resetsAt` and the window duration), no run-out verdict until 8% of the window has elapsed. Stateless; don't reintroduce sample history.
- Only Claude Code's token is ever refreshed, and only after it has expired (Claude Code itself refreshes 5 minutes early, so a running Claude Code always wins). `ClaudeCodeCredentialStore` follows Claude Code 2.1's own protocol, verified from its binary: take `~/.claude/.oauth_refresh.lock` then `~/.claude.lock` (proper-lockfile directories, stale after 60s), re-read under the lock and adopt a token another process landed, POST the refresh with the stored scopes verbatim, then write back under `~/.claude/.storage-write.lock` only if the stored refresh token is still the one used, through `security -i` with the JSON hex-encoded, exactly as Claude Code writes it. `ClaudeTokenRefresh` holds the pure decide/merge logic. The refresh runs in a detached task so a cancelled poll can never abandon it after the server rotated the token. On `invalid_grant` storage is left alone and the dead token is remembered until Claude Code stores a different one. No other provider refreshes: Codex tokens last ten days and OpenAI rejects reused refresh tokens, Cursor.app rotates its own, OpenCode keys never expire.

## Releases

- Tagging is the release. `git push origin vX.Y.Z` runs `.github/workflows/release.yml`, which archives, notarizes, builds a DMG, publishes the GitHub release and deploys the Sparkle appcast to Pages. Nothing is built from a laptop. See `RELEASING.md`.
- Never hand-edit `MARKETING_VERSION` or `CURRENT_PROJECT_VERSION`; CI injects both from the tag and the run number. Sparkle compares `CURRENT_PROJECT_VERSION`, so a stale value hides the update from everyone.
- `SUFeedURL` is compiled into every shipped binary and can never change. Front it with a redirect if a custom domain is ever wanted.
- The app icon is generated: `Scripts/AppIcon.svg` (the website icon, viewBox widened to inset it to the macOS icon grid) rendered by `Scripts/make-appicon.sh`. Edit the SVG and re-run the script, never the PNGs.

## Constraints

- The pbxproj uses file-system-synced groups (objectVersion 77). New files under `Notchlet/` or `NotchletTests/` join the target automatically; never hand-edit the pbxproj to add source files. The one hand-maintained part is the `Embed Helpers` copy phase and the `Vendor` group that put the betterleaks binary in `Contents/MacOS`.
- Swift 6 language mode with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and approachable concurrency.
- Providers must never consume usage when fetching it, and must not talk to anything except the CLI's own local state and usage endpoints. The secret scanner never validates a key against anyone's API.
- Keep pure logic (geometry, parsing) out of AppKit types so it stays testable.
- macOS 14 deployment target.
